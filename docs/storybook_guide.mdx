# Storybook 가이드

## 목적

Storybook은 UI 컴포넌트를 독립적으로 개발하고 문서화하기 위한 도구입니다.

우리 프로젝트에서는 FSD(Feature-Sliced Design) 구조를 따르며, 컴포넌트와 관련된 Story 파일을 동일한 위치에 배치(Co-location)하여 관리합니다. 이를 통해 컴포넌트, 테스트, 스토리를 한 곳에서 확인할 수 있으며 유지보수성을 높일 수 있습니다.

---

## 디렉토리 구조

```
src/
├── shared/
├── entities/
├── features/
├── widgets/
└── views/
.storybook/
├── main.ts
├── preview.ts
└── manager.ts
docs/
├── Introduction.mdx
├── DesignSystem.mdx
└── Contributing.mdx
```

### .storybook

Storybook 설정 파일을 관리합니다.

- main.ts : Storybook 기본 설정
- preview.ts : 전역 Decorator, Parameters 설정
- manager.ts : Storybook UI 커스터마이징

### docs

컴포넌트와 직접적으로 연결되지 않는 문서를 관리합니다.

예시:

- 프로젝트 소개
- 디자인 시스템 가이드
- 컬러 시스템
- 타이포그래피
- 컨벤션
- 기여 가이드

---

## 컴포넌트 스토리 구조

각 컴포넌트의 Story 파일은 컴포넌트와 같은 위치에 배치합니다.

```
src/
├── shared/
│   └── ui/
│       └── Button/
│           ├── Button.tsx
│           ├── Button.stories.tsx
│           └── Button.styles.ts
│
├── entities/
│   └── user/
│       └── ui/
│           └── UserCard/
│               ├── UserCard.tsx
│               ├── UserCard.stories.tsx
│               └── UserCard.test.tsx
│
├── features/
│   └── auth/
│       └── ui/
│           └── LoginForm/
│               ├── LoginForm.tsx
│               └── LoginForm.stories.tsx
```

## 스토리 작성 대상

Storybook은 재사용 가능한 UI 컴포넌트와 사용자 인터랙션을 포함하는 주요 컴포넌트를 문서화하는 용도로 사용합니다.

### 작성 권장 (선택)

#### Shared UI

text Button Input Textarea Modal Toast BottomSheet Dropdown

#### Entities UI

text UserCard RestaurantCard ReviewCard ProfileCard

#### Feature UI

text LoginForm SignupForm CreateTeamForm MatchCard

### 작성 비권장

#### 페이지 단위 컴포넌트

text HomePage MyPage RestaurantDetailPage

페이지는 여러 컴포넌트 조합으로 구성되므로 Storybook 관리 대상에서 제외합니다.

#### 단순 레이아웃 컴포넌트

text Flex Stack Container Spacer

별도 동작이나 상태가 없는 경우 스토리 작성 대상에서 제외합니다.

## 문서(MDX) 작성 기준

### docs 폴더

프로젝트 공통 문서

```text
 docs/
  ├── Introduction.mdx
  ├── DesignSystem.mdx
  └── Contributing.mdx
```

### 컴포넌트별 문서

특정 컴포넌트에 대한 상세 가이드가 필요한 경우 컴포넌트 폴더 내부에 작성할 수 있습니다.

```text
 Button/
  ├── index.ts
  ├── Button.tsx
  ├── Button.stories.tsx
  └── Button.mdx
```

예시:

- 사용 방법
- 접근성 가이드
- 디자인 규칙
- Variant 설명
- 사용 시 주의사항

## 운영 원칙

1. 컴포넌트와 Story 파일은 같은 위치에 둔다.
2. Storybook은 UI 문서화 및 개발 검증 도구로 활용한다.
3. 재사용 가능한 컴포넌트 위주로 Story를 작성한다.
4. 프로젝트 공통 문서는 docs 폴더에서 관리한다.
5. Story 작성 시 다양한 상태(Default, Loading, Error, Disabled 등)를 함께 제공한다.
6. 새로운 공용 컴포넌트 추가 시 Story 작성도 함께 진행한다.
